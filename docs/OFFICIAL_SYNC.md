# OFFICIAL_SYNC — 官方同步中心

> 從「官方登記助手」升級為 **Official Sync Center**：企業級的資料整備、差異比對與引導送出。
> **紅線**：合法、不繞驗證、不模擬登入、不儲存官方密碼。最終由使用者本人在官網送出。
> 狀態：**Proposed**。

## 1. 現實限制（設計前提）

| 限制 | 影響 | 我們的合法對策 |
| --- | --- | --- |
| 官方**沒有 API** | 無法程式化讀寫 | 以「結構化匯出/匯入 + 引導填寫」橋接 |
| **驗證碼** | 無法自動登入 | 由使用者本人輸入，平台不介入 |
| **20 分鐘自動登出** | 操作視窗短 | 用 Session 視窗協調，**批次**一次完成最多工作 |
| 資料格式易變 | 匯入解析脆弱 | 版本化 mapping + 容錯解析 + 明確錯誤提示 |

## 2. 設計理念

> 我們不「代替使用者登入」，我們讓使用者「登入後 10 分鐘內把該做的事一次做完」，並確保**平台資料與官方資料一致**。

三大支柱：**Prepare（整備）→ Reconcile（比對）→ Guide（引導）**。

## 3. 功能組件

### A. 資料整備（Prepare）
- 從平台資料自動產生「待登記/待更新」清單（哪些寵物尚未官方登記、哪些欄位有變動）。
- 產生**官方欄位對應**的整備包（依官方 Excel 欄位順序/格式），供使用者對照或匯入官方系統。
- AI 檢查缺漏（晶片號、出生日、來源母犬貓等必填），先補齊再登記。

### B. 差異比對（Reconcile）
- 使用者從官網下載名下寵物 Excel → 上傳平台 → **diff 引擎**比對官方 vs 平台：
  - 官方有、平台無 → 匯入建議
  - 平台有、官方無 → 待登記
  - 兩邊不一致（絕育狀態、飼主、除戶）→ **drift** 警示
- 產出可執行的 **待辦清單**（`official_registrations.sync_state = drift/ready`）。

### C. 引導送出（Guide）
- **Session 視窗協調**（Durable Object）：使用者按「開始同步」→ 開一個 20 分鐘工作階段，平台列出這次要送出的**批次項目**與每項的欄位值（可一鍵複製）。
- **瀏覽器擴充/書籤小工具（選配、合法）**：在**使用者自己已登入的官網分頁**中，把平台整備好的欄位值**貼入表單欄位**輔助填寫；**驗證碼與送出仍由使用者本人完成**。擴充只在使用者主動啟用時運作，不儲存官方憑證、不背景自動化。
- 送出後，使用者回填「已送出」→ 平台標記 `submitted_by_user`，下次以官方匯出核對確認。

## 4. 明確禁止（合規紅線）

- ❌ 破解 / 自動辨識驗證碼
- ❌ 自動 / 模擬登入、代管官方帳密
- ❌ 伺服器代理抓取官網、繞過 session 限制
- ❌ 任何違反官方使用條款之自動化送出

## 5. 資料模型銜接

- `official_registrations`（見 DATABASE）：`sync_state ∈ draft/ready/submitted_by_user/confirmed/drift`，`last_diff jsonb`。
- 所有同步動作寫 `audit_logs`（誰、何時、送了哪些）。
- 官方匯出檔只做解析比對，**不長期保存原始個資檔**（解析後即棄，符合最小保存）。

## 6. 使用者體驗目標

- 登入前把所有整備做完 → 登入後只做「貼上 + 驗證碼 + 送出」。
- 一次 Session 完成一批，避免反覆登入。
- 清楚的「官方 vs 平台」差異視圖，讓業者信任資料一致。

## 7. 風險與備援

- 官方頁面/格式改版 → mapping 版本化 + 監控 + 快速修補；解析失敗給明確指引。
- 擴充維護成本 → 擴充為「選配增強」，核心價值（整備 + 比對）不依賴擴充也成立。
